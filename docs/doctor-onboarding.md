# Doctor onboarding and launch checks

1. In Admin → Doctor registration, enter only the doctor's email. Before sending the one-time invitation, confirm you already verified their qualifications and they agreed to be invited. A confirmed Tuta account on the same email is linked instead of receiving a new authentication email; send that doctor the profile setup link from the list so they can sign in with their existing account. Outstanding invitations can be resent from the list.
2. The doctor opens the email on the web and sets a password, then enters their first name, last name and specialty. A profile photo is optional (JPG, PNG or WebP, up to 3 MB). The form explicitly asks for permission to publish these fields.
3. The completed profile is published without further approval. Use Admin → Doctors and visits to add appointment availability. Legacy registrations awaiting manual verification continue to use their existing process. Subsequent sign-ins use the same email and password. On iOS and Android, open Services → Doctors, chat & appointments.
4. The doctor workspace shows only the doctor's own patient chats and bookings. Doctors can reply and cancel an owned booking. The admin manages profile edits, availability and rescheduling. A doctor role is not an admin role and does not grant access to private patient journals.
5. In Admin → Doctor registration, use **Remove doctor record** to remove a registration and, when verified, its professional profile and badge. It does not delete the underlying Tuta login. Bookings or conversation records block removal; for those profiles, turn off the profile in **Doctors and visits** instead. The 48-hour message deletion schedule is unchanged; it does not delete the conversation record.

Before the first real invite, use a controlled test inbox. Check that Supabase allows the exact website `/reset-password` redirect and that the Invite user template includes the confirmation link. Confirm mail arrives, the link works once, and a regular account cannot access the doctor setup. In an isolated environment, confirm the finished profile is immediately listed and then test a booking, a message and a doctor reply with a second controlled account. Do not use real patient records.
